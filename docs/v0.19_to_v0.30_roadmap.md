# BeeEmUu v0.19.0 to v0.30.0 - Planning Map

> **Status:** Proposed planning horizon. This document does not create,
> publish, or promise releases. Each cycle needs its own implementation plan,
> validation evidence, and release decision.

## Planning principles

- Keep vehicle-facing protocol, transport, and ECU-write work behind a Tier B
  review and real-car validation gate.
- Prefer independently useful Tier A increments: data quality, analysis,
  documentation, test coverage, and UI clarity.
- Do not add service writes, flashing, BLE/WiFi adapters, or cloud sync to a
  cycle until safety, privacy, and operational ownership are explicit.
- Treat real-car evidence as a dependency, not a release afterthought.

## Milestones and gates

### v0.19.0-v0.21.0: local analysis foundation

Finish reporting, responsive/accessibility polish, and portable log replay.
Success means a user can capture, annotate, export, import, and understand a
local diagnostic trace without a hosted account.

### v0.22.0-v0.24.0: evidence and coverage

Prioritize validation artifacts and data confidence before expanding protocol
behavior. New PIDs, DIDs, or profile values require provenance and an explicit
verification state.

### v0.25.0-v0.28.0: hardware reliability research

Any transport behavior change requires Tier B review, isolated timing checks,
and real-car testing. Adapter support remains a research deliverable until a
repeatable compatibility contract exists.

### v0.29.0-v0.30.0: quality and stabilization

Build a release-quality floor from validated fixtures and close only work that
has supporting evidence. Do not use v0.30.0 as a feature dump.

## Decisions required before Tier B implementation

1. Which real-car owners and adapters can supply repeatable validation runs?
2. What compatibility promise, if any, should BeeEmUu make for BLE and WiFi?
3. Which read-only service results are sufficiently sourced to promote from
   research into community profiles?
4. What release criteria turn an implementation-complete cycle into a tagged
   release?
