# BeeEmUu v5.3 — working plan

Status: proposed (2026-11-27, after the v5.2.0 "Offline Marketplace" release).
Theme candidate: **Plugin Confidence** — make community plugins easier to
trust, install and keep current anywhere, and make app updates visible
instead of silent.

This is a planning document, not a commitment. Scope is confirmed when the
release branch opens. Everything listed stays inside the established safety
model: plugins never get vehicle-write capabilities, and every package is
verified before install.

## What v5.1.0 / v5.2.0 already shipped (baseline)

- Plugins tab marketplace: browse, consent preview, install, enable/disable,
  sandboxed run, remove (v5.1.0).
- Signed desktop auto-updates (minisign keypair, `latest.json`) (v5.1.0).
- Offline registry cache, offline management of installed plugins, Update
  all, enabled-state preservation, marketplace filter (v5.2.0).

## Proposed v5.3 scope

### P0 — small surface, high daily value

1. **Sideload install from a local `.zip`.**
   The last offline gap: browsing and managing work offline (v5.2.0), but
   installing still requires the registry. Let a user pick a marketplace zip
   on disk; compute its SHA-256 locally and show the full digest in the
   consent dialog (there is no registry to check against — the consent text
   must say so plainly), validate `plugin.json` through the same
   `extractPackage` path, then install disabled.
   Acceptance: installs a valid zip offline; refuses id/version-manipulated
   or malformed archives; consent clearly marks "unverified source — no
   registry digest to compare"; jsdom tests for the flow.

2. **Visible auto-update status + manual check.**
   Today `auto_update.js` writes to `#status-log` only. Add an update line
   in Settings/About: current version, "Check for updates" button, download
   progress (updater download events), and a link to the release notes.
   The existing rule stands: never download or relaunch while a vehicle is
   connected.
   Acceptance: manual check reports up-to-date / available / error;
   progress visible during download; no behavior change to the automatic
   idle loop.

### P1 — trust and ecosystem

3. **Signed registry.** Sign `registry.json` with a minisign key owned by
   the marketplace repo (same tooling as release signing); the app verifies
   the signature against a plugins pubkey baked into the build before
   listing anything. Removes the single point where a compromised static
   host could repoint download URLs (package sha256 currently limits, but
   does not fully close, that path). Keep an unsigned-registry fallback
   with a visible "unverified registry" notice for the transition window.
   Acceptance: tampered registry refused with a clear error; valid legacy
   registry still browsable with the notice; tests cover both.

4. **Plugin release notes on update consent.** Optional `changelog` field
   in the registry schema; shown in the single-update and Update-all
   consent views so users see what changed before replacing a working
   plugin. Backwards compatible (older entries simply have no notes).

### P2 — nice to have, only if the release is ahead of schedule

5. **Category tabs + sort control** in the marketplace grid (diagnostics,
   coding, reporting, data, ui, tools), building on the v5.2.0 filter.
6. **Plugin storage insight**: per-plugin stored size in the card, with a
   "clear plugin data" action for entries that use iframe-local storage.
7. **Plugin submission starter**: `packages/template/` in beemuu-plugins
   plus a short AUTHORING.md (manifest fields, zip layout, validator
   invocation) so community authors need zero tribal knowledge.

## Non-goals for v5.3

- No vehicle-write capabilities for plugins (permanent rule).
- No installer Authenticode purchase/setup (SmartScreen reputation is a
  separate, cost-bearing project; revisit when download volume justifies).
- No backend rewrite of plugins.beemuu.com; the static-registry model stays.

## Release gates (unchanged)

- Full JS suite + Rust + Python backend green in CI; new logic covered by
  node/jsdom tests.
- `scripts/stamp-release.py v5.3.0` across every surface, CHANGELOG section,
  RELEASE_NOTES_v5.3.0.md.
- Tag → signed release build → verify `.sig` assets + `latest.json` →
  dispatch update-on-release → confirm beemuu.com and plugins.beemuu.com.
