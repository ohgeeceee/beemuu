# v0.14.2 Plan — "Live Data on the Bench"

*Drafted 2026-07-27 against `main` @ 653c154 (v0.14.0 "Live CAN" Tier A
complete + v0.14.1 PR #169 issue #161 fix merged + PR #170 freeze-schema
split landed).*

## Premise

The user is going real-car with a K+DCAN cable on a 2007 E70 X5 4.8L
(N62/BTU, MSV80-family DME, D-CAN @ 500 kbps). v0.14.0's Tier B
(`can_listener.rs` raw-CAN transport + `get_latest_can_frames`) was
explicitly gated behind an OBDLink SX cable (per
`docs/v0.14.0_plan.md`).

**The K+DCAN cable cannot passively listen to raw broadcast frames**
(see `src-tauri/src/transport/kdcan.rs` doc-comment lines 1-15 +
`src-tauri/src/transport/isotp.rs` lines 1-22 — the FTDI firmware
terminates ISO-TP upstream on both D-CAN and K-line; raw-CAN-class
transports "none of those transports exists yet"). v0.14.0 Tier B
slices 5/6 are deferred behind the OBDLink SX acquisition — they are
not this cycle's problem.

**This cycle ships "live data today, on the bench, with the cable you
have."** Three deliverables, all Tier A. No `transport/**` changes.
No new crate. No new Tauri command — `read_live_data` and `watch_*`
already work over K+DCAN today.

## What this cycle ships

### Slice 1 — Enrich `community/profiles/n62.toml` (Tier A, data only)

The existing `n62.toml` already covers the emissions-mandated OBD-II
PIDs (`0x0C`, `0x05`, `0x0F`, `0x04`, `0x11`, `0x0B`, `0x0D`, `0x42`,
`0x46`) plus an unverified `local:10` oil-temp placeholder. This
slice:

- Adds the OBD-II PIDs that BMW E-series DMEs reliably support
  beyond the emissions-mandated set:
  - `0x5C` Engine oil temperature (the textbook BMW-on-OBD-II
    oil-temp PID — almost always present on N62 ME9.2; the
    placeholder `local:10` is unverified per
    `docs/ROADMAP_ISSUES.md` issue 3 and should be **removed**
    once `0x5C` is verified on the E70).
  - `0x5E` Engine fuel rate (L/h, encoded `u16_quarter`).
  - `0x5F` Engine runtime (sec since start, encoded `u32` BE).
  - `0x62` Engine fuel rate (g/s, encoded `u16_milli`).
- Adds `[[profile.notes]]` for the N62's known instrumentation:
  which PIDs to watch for slow coolant warm-up (a documented
  N62 valley-pan failure mode), which to ignore, which are
  sleep-sensitive.

Each new entry carries a clear evidence marker per the project's
data-discipline convention (see `docs/DECODE_FUNCTIONS.md`);
the harness doc (slice 3) provides the verification path.

### Slice 2 — Live Data panel UX polish (Tier A, frontend only)

The existing Live Data panel (`src/index.html:146-` +
`src/js/main.js:1260-`) works but is minimal: hardcoded 250 ms
poll, no peak tracking, no range bar, no NRC error surface, no
CSV snapshot. This slice:

- Adds a polling-rate selector (100 / 250 / 500 / 1000 ms).
- Adds per-gauge peak tracking (mirrors the v0.14.0 live-gauges
  peak pattern; surfaces as a side-panel "Current peaks" table).
- Adds a `range` bar under each gauge so the user can read
  "88 °C on a 90 °C hot scale" at a glance.
- Adds a "Save snapshot" button that writes the current values
  to `<HOME>/beeemuu/live-snapshots/<timestamp>.csv`.
- Wraps the poll loop so a NRC response is logged with the
  `(sid, nrc)` pair (e.g. `0x22 0x1234: 7F 22 31`) and the
  affected gauge dims to "unsupported." One-click removal of
  the offending PID from the profile.

### Slice 3 — `docs/validation/n62-real-car.md` (Tier A, docs only)

Same shape as `docs/validation/can-broadcast.md` /
`docs/service-functions.md`. Step-by-step:

1. Connect K+DCAN cable to E70 OBD-II port (pin 6+14 for D-CAN;
   pin 7 for K-line fallback if the DME does not respond).
2. Run app, click Connect, select `n62` profile, click Live Data.
3. For each profile.param: expected byte layout, expected value
   at key-off / idle / cruise, what to do if the PID does not
   respond (Parameter Explorer → `read_did` raw).
4. **Specifically calls out** the `local:10` → `0x5C` swap: if
   `0x5C` responds with sensible oil-temp values across the
   warm-up cycle, the `local:10` entry in `n62.toml` should be
   removed and the profile regenerated. This is the single
   highest-value piece of real-car evidence the E70 can
   produce for the wider community.

## What we will NOT do (this cycle)

- **Touch `transport/**`.** No new transport module, no raw-CAN
  listener, no passive bus sniffer. The K+DCAN cable cannot do
  passive listen at the firmware level; building that on the
  K+DCAN cable is out of scope.
- **Touch `protocol/`.** UDS/KWP request builders stay unchanged.
- **Add a new crate.** No `tokio-serial` / `nb-sys` / `peak-can`
  / `socketcan`. `serialport = "4"` (already in `Cargo.toml`)
  covers everything we need.
- **Modify the v0.14.0 Live Gauges panel.** The user explicitly
  opted to leave it as sim-only (Option B per the cycle-pick
  conversation). The DID-projection bridge that would feed the
  Live Gauges panel from the existing `read_live_data` path is
  **deferred to v0.14.3 or later**, behind the user's call.
- **Cut a release tag.** Tier C, requires the user's call.
