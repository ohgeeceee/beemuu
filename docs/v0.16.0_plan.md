# BeeEmUu v0.16.0 — Cycle Plan

> **Status:** v0.15.x shipped 2026-08-30 (0.15.1-0.15.9 via #257/#258). This doc is the proposed v0.16.0 cycle shape for maintainer review. Per `COMMUNITY_FRAMEWORK.md` "no feature without a Discussion", no v0.16.0 work should land before a Discussion thread opens.

## Premise

v0.15.x delivered the **tuner logging workflow** (injector duty, triggers, math channels, workspace) + **external log import** + **CAN validation harness** + **vehicle DB**. What's left is **sharing** — getting a log off the laptop without emailing a CSV.

v0.16.0 picks cycle name **"Share the Trace"** because the work is about turning the now-rich logging pipeline into a shareable artifact: a web-based viewer for shared logs (no app needed to view a friend's trace), plus the small docs that make sharing trustworthy.

This is the narrowest defensible scope consistent with 3-PR spine shape. Each item ships independently.

## Cycle scope (proposed)

**Three small PRs**, in order.

### PR #1 — Web-based shared-log viewer (read-only)

**Why first.** The single most-requested backlog item after "log more channels" is "let my friend view my log without installing the app". The hosted backend (`backend/` on `beemuu.com`) already serves `/api/health` and `/api/stats`; a read-only `/api/logs/:id` plus a static `frontend/log-viewer.html` that reuses `src/js/svg_export.js` `chartToSvg` is ~200 lines.

**Files**
- `backend/app.py` — `GET /api/logs/:id` (read-only, no auth, id = sha256 of CSV, stored under `~/beeemuu-shared/` on VPS)
- `frontend/log-viewer.html` (new) — static page, takes `?id=abc`, fetches `/api/logs/abc`, renders via `chartToSvg` (no Chart.js needed)
- `src/js/log_share.js` (new) — `shareLog(csvText) -> id` (POST to `/api/logs`, returns id + viewer URL)
- `src/index.html` / `src/js/main.js` — "Share log" button next to "Export CSV" in Logging tab
- `src/js/test/log_share.test.cjs` (new) — `shareLog` mock fetch test

**Acceptance.** User clicks Share, gets `https://beemuu.com/log-viewer.html?id=abc`, friend without app sees chart. `cargo test` + `node --test` pass.

### PR #2 — Automatic BMW service manual lookup (per-DTC)

**Why second.** Every DTC row already has a "Related schematics" panel (CC0 wiring diagrams). The next step is a one-line service manual lookup: DTC `2A82` -> `https://www.newtis.info/tisv2/a/en/...` (or `bmwtis.com` fallback). No corpus to host, just a URL builder.

**Files**
- `src/js/service_manual.js` (new) — `manualUrl(dtcCode) -> string|null` (map from `community/dtc_texts.toml` prefix to newtis path)
- `src/js/test/service_manual.test.cjs` (new) — 5 DTC -> URL cases
- `src/index.html` / `src/js/main.js` — "Service manual" link in DTC detail panel

**Acceptance.** Clicking DTC shows manual link if known, otherwise hidden. Pure JS, no Rust.

### PR #3 — Multi-language UI (DE/EN starter)

**Why third.** Broader audience, low risk: i18n is a solved problem via a JSON dictionary, and the app already has a single `src/index.html` with all strings. Ship DE + EN starter (50 strings), defer FR/CN to next cycle.

**Files**
- `src/js/i18n.js` (new) — `t(key) -> string`, `setLang(lang)`, `localStorage.beeemuu.lang`
- `community/i18n/de.json` / `en.json` (new) — 50 keys
- `src/index.html` — `data-i18n` attrs, language selector in header
- `src/js/test/i18n.test.cjs` (new) — `t` fallback test

**Acceptance.** Toggle DE/EN, all 50 strings switch without reload, `node --test` pass.

## What does NOT ship in v0.16.0 (deferred)

- Cloud sync (opt-in log upload with auth) — needs privacy + ops story, v0.16.0's share is anonymous + read-only, no account
- Raspberry Pi CAN bridge — hardware project
- Bootmod3/MHD flash (write) — legal risk, stays deferred per `docs/proposals/bootmod3-mhd-scope.md`
- Full vehicle database enrichment beyond VIN prefix — needs real build-sheet corpus
