## Premise

v0.7.0 / v0.8.0 / v0.9.0 / v0.10.0 shipped the walkthrough
bundle, the test-plan walk reducer, the verified routine
marker, and the share-as-HTML export — all on the
**simulator**. v0.15.1 ports the test-plan walk to
**real-car sessions**: walks against the K+DCAN cable,
records results against the real freeze-frame data,
exports to the same self-contained HTML.

This is the load-bearing user-facing win of v0.15.1: an
E90 / E60 / E70 owner with the $15 K+DCAN cable can now
**run a routine test plan against the actual car** —
walking through the DME adaptation bleed, the injector
registration, the battery registration, etc. — and
**share the result as a self-contained HTML** the buyer
or the shop can review without needing the Beemuu app.

The v0.15.0 DID-projection bridge is the optional
power-up: a walk step that needs a single live-data
value (engine RPM at idle, coolant temp at warm-up, oil
temp at warm-up) can read it through the bridge. Without
it, the walk falls back to the existing
`read_freeze_frame` async command (already shipped in
v0.11.0 / PR #142).

## What this cycle ships

The cycle's spine is a 3-slice shape:

### Slice 0 — `docs(v0.15.1): cycle plan + ROADMAP header + CHANGELOG entry` (Tier A, docs only)

This PR. The cycle plan doc, the ROADMAP v0.15.1 cycle
block, the CHANGELOG `## [0.15.1] — Unreleased`
section. Pure docs.

### Slice 1 — `Test-plan walk on real freeze-frames` (Tier A, frontend)

Wires the existing `testplan_walk.js` reducer (v0.9.0 /
PR #134) to read from the **real** `read_freeze_frame`
Tauri command instead of the simulator's snapshot. The
walk step lookup table maps each routine's "expected
freeze-frame fields" to the DME-specific schema
(v0.14.0 freeze-frame schema split, PR #170). Pure
mapping logic. ~80 LOC + 4 unit tests.

### Slice 2 — `record_walk_result` async Tauri command (Tier B, Rust)

New `#[tauri::command]` that saves a walk outcome
(passed / failed / skipped per step) to
`<HOME>/beeemuu/walks/<timestamp>.json`. Mirrors the
v0.12.0 DTC history pattern. Touches
`src-tauri/src/commands.rs` (protected path —
Tier B). Flag the protected path at the top of the PR
body; human merges after the auto-merge bot's CI gate
passes. ~60 LOC + 3 integration tests in
`src-tauri/tests/async_commands.rs`.

The new command is `async fn` (per the project's
hardware-timing invariant). `tests/async_commands.rs`
allowlist guard applies.

### Slice 3 — `Walk export to HTML includes real freeze-frame snippets` (Tier A, frontend)

The v0.11.0 share-as-HTML PR (#142) embeds the
freeze-frame in the HTML. This slice ensures the
embedded freeze-frame is the **real one** for walks on
real cars, not the simulator's. The exporter already
serializes whatever's in the walk's per-step result —
the slice is mostly a CSS / layout touchup to show the
real-data badge prominently. ~30 LOC + 2 unit tests.

## What this cycle does NOT ship

- ❌ No new transport support (BLE / WiFi / ENET
  auto-detect). The forward-roadmap doc's `v0.16.0`
  cycle spine ("Tier B Land Rush — BLE / WiFi /
  ENET") is the next cycle's work.
- ❌ No `protocol/**` code changes. The
  `read_freeze_frame` async path is already shipped (it's
  what the v0.11.0 / PR #142 freeze-frame schema split
  uses). v0.15.1 only adds the `record_walk_result` write
  surface + the freeze-frame wiring in the walk reducer.
- ❌ No `transport/**` code changes. Reuses the
  existing K+DCAN transport for the real-car reads.
- ❌ No new crates in `src-tauri/Cargo.toml`. The
  `tauri-plugin-dialog` crate added in v0.14.1
  (PR #169) is the only new runtime crate across
  v0.14.x. v0.15.1 reuses it for the walk-result-saved
  confirmation dialog (per the v0.14.3 PR #190 frontend
  rewire pattern).
- ❌ No community data changes (the walk reducer
  works against the existing `community/profiles/*.toml`
  data shape; no new DIDs, no new decoders, no new
  profile entries).
- ❌ No new BMW hex descriptions.
- ❌ No `git tag v0.15.1` (Tier C release cut,
  separate step after all 3 slices land).

## Execution order

Slices 0 → 1 → 2 → 3 land in this order. Slice 0 ships
first (this PR). Slice 1 ships second (the walk reducer
rewrite). Slice 2 ships third (the new async Tauri
command). Slice 3 ships fourth (the HTML export
touchup). The natural cadence is 4 sequential PRs over
~3-5 days.

The release-cut PR (the Tier C step) merges after
slice 3 lands; after that, the maintainer runs
`git tag v0.15.1 && git push --tags` to trigger
`release.yml`.
