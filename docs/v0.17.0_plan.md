# BeeEmUu v0.17.0 — Cycle Plan

> **Status:** Planned. Ships after v0.16.1 patch.

## Premise

v0.16.0 shipped the "Share the Trace" feature cycle. v0.17.0 tackles
the **E-series data desert** — the structural gap where the open-source
community has no published KWP2000 local identifier table for BMW E-series
DMEs (MSV70, MSV80, MSD80, MSD81, ME9.2).

The approach: expand the CAN broadcast decoders beyond the 6 known IDs,
add more E-series-specific DTC texts, and grow the vehicle DB with
E60/E90/E9x prefixes that are underrepresented.

## Cycle scope

### PR #1 — CAN broadcast decoder expansion (Tier A)

Expand `src/js/can_decoders.js` with additional broadcast IDs observed
on E9x/E6x chassis. Current 6 IDs: 0x0AA, 0x1D0, 0x545, 0x0CE,
0x130, 0x316. Add decoder functions for any new IDs discovered via
the validation harness.

**Files**
- `src/js/can_decoders.js` — new decoder functions
- `src/js/test/can_decoders.test.cjs` — new test cases
- `docs/validation/can-broadcast.md` — updated harness with new IDs

**Acceptance.** All existing + new decoder tests pass. Validation
harness runs against new fixture data.

### PR #2 — E-series DTC text expansion (Tier A)

Add DTC texts for E90/E9x-specific fault codes not yet in
`community/dtc_texts.toml`. Focus on:
- DME codes common on N52/N54 (valvetronic, VANOS, misfire)
- EGS codes (EGS 6HP transmission)
- DSC codes (stable dynamics control)

**Files**
- `community/dtc_texts.toml` — new entries
- `src/js/test/dtc_texts.test.cjs` — verify overlay loads

**Acceptance.** `node --test` passes. New codes render in Diagnostics
tab.

### PR #3 — Vehicle DB E-series growth (Tier A)

Add more VIN prefixes for E60, E90, E91, E92, E9x chassis to
`community/vehicle_db.toml`. Focus on N52 and N54 variants that are
underrepresented.

**Files**
- `community/vehicle_db.toml` — new prefix entries
- `src/js/test/vehicle_db.test.cjs` — new test cases

**Acceptance.** `lookupVin` returns correct build sheets for new
prefixes. All tests pass.

## What does NOT ship in v0.17.0

- ❌ No `transport/**` code changes (BLE / WiFi / ENET deferred)
- ❌ No `protocol/**` code changes
- ❌ No `commands.rs` changes
- ❌ No ECU write routines
