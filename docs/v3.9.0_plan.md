# Plan — v3.9.0 "Drive Cycle Analyst"

**Parent:** `docs/v3.8_to_v5.0_roadmap.md` (schedule of record)
**Tier:** A — pure analysis over a recorded log, plus a read-only panel.
**Depends on:** v3.8.0 (a cycle verdict is only as good as the channels it is
computed from; the integrity pass runs first).

## Why

Everything the app measures is measured *somewhere in a log*, and a log is not
a unit a human reasons about. A **drive cycle** is: key on, driven, key off.
Most real findings are cycle-shaped — "it stumbles for the first 90 seconds",
"it never gets out of warm-up on the school run", "the short trips are all
idle". Segmenting the log into cycles turns a wall of samples into a handful of
trips with names, and it is the unit the v4.0.0 fleet board summarises.

## Slices

### S1 — `detectEngineStarts(points, opts)`
Find every moment rpm leaves 0. Returns `[{ at_s, rpm }]`. A single stray
non-zero sample is not a start (see `MIN_START_SAMPLES`); a start is
acknowledged only when the engine is actually running.

### S2 — `segment(series, opts)`
Split a whole log into cycles. A cycle ends when rpm returns to 0 and **stays**
there for at least `STOP_HOLD_S` of continuous idle — a traffic light is not the
end of a trip. Returns
`{ cycles: [{ index, start_s, end_s, duration_s, points }], gaps, reason }`,
where `gaps` records inter-cycle holes and `reason` explains an empty result
("no rpm channel", "no engine start found"). A log that never sees rpm return
to zero yields one open cycle marked as such, not zero cycles.

### S3 — Per-cycle metrics
- `warmUpSeconds(points, opts)` — seconds from cycle start until coolant first
  reaches `WARM_TARGET_C` (default 90 °C), or **`null` if it never does**. A
  car that never warms on a 4-minute trip is a finding, not an error.
- `idleRatio(points, opts)` — share of the cycle below `IDLE_RPM`.
- `classify(cycle)` — `{ cold_start, warm_up_s, idle_ratio, avg_rpm, max_rpm,
  verdict, score, evidence }`. Cold start is a *measured* coolant-low-at-start
  condition, never an assumption.

### S4 — `analyze(series, opts)`
`{ cycles, summary: { n_cycles, cold_starts, total_duration_s, total_idle_s,
headline, cold_warmup_concerns } }`, cycles worst-first.

### S5 — Panel — "Drive cycles"
One card per cycle: duration, idle share, cold-start flag, warm-up seconds, and
the engine's `evidence`. Cycles with an unmeasured quantity say so; the panel
never renders a `null` warm-up as "0 s".

### S6 — Release cut (stamp → gen → test → push → tag → publish → deploy).

## Refusal contract (non-negotiable)

When the input cannot support a verdict — no rpm channel, fewer than the
minimum samples, no engine start — the engine returns an explicit
`unknown`/`no_cycles` verdict with `score: null`, `confidence: 0` and a reason
array naming what was missing. **It never fabricates a drive cycle or a grade
from insufficient data.** This is the single most-tested behaviour in the cycle.

## Acceptance criteria

- `node --test src/js/test/drive_cycle.test.cjs` green; full suite green.
- A two-cycle log segments into exactly two cycles with correct boundaries.
- A cycle that never ends is reported as one open cycle, not dropped.
- No rpm channel ⇒ `unknown`, `score: null`, an explanatory reason.
- A healthy warm cycle scores above a cold start with a long idle, for the
  stated reasons.
- Every number in a verdict traces to a named exported constant or a computed
  metric.

## Non-goals

- Route, GPS or distance. This cycle reads rpm, coolant and time.
- Regeneration/DPF modelling — noted as a candidate, deliberately not in scope
  until a log with the required channels is in hand.
