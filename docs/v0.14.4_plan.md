## Premise

v0.14.3 was the last cycle that shipped user-visible
features. The cycles before it (v0.14.0 through v0.14.2) shipped
real diagnostic capabilities — the Live Gauges panel, the
N62 real-car harness doc, the Live Data panel UX polish, the
N62 PID enrichment, and the per-PID NRC backend + frontend
re-wiring. But **none of these cycles audited or
strengthened the supporting infrastructure**:

- The **Diagnostic Story** feature (`story.rs`, 350 LOC) — the
  one-click mechanic narrative modal at `src/index.html:513`
  and `src/js/main.js:2961` (`renderStory`) — had **zero
  unit tests**. The pure-function surface (severity
  bucketing, cost-range parser, vehicle-formatter,
  full-pipeline generation against the community knowledge
  base) was completely untested.
- The **Secure Snapshot Share** feature (`anonymize.rs`, 113
  LOC) — the VIN-stripping privacy layer at
  `src/js/main.js:1071` (`doSecureShare`) — also had **zero
  unit tests**. The privacy guarantees (VIN never leaks,
  vehicle_fingerprint is stable for a given VIN, mileage is
  stripped, the diagnostic content survives) were
  unverified by automated checks.
- The **CLAUDE.md "Hardware & timing invariants"** section
  still claimed `keepalive`, `ISO-TP multi-frame`, and `read_vin`
  were `NOT YET IMPLEMENTED` even though all three shipped
  months ago.
- The **ROADMAP.md v0.3.0 historical section** had six "🟢
  Ready" items that had actually shipped but were never
  re-tagged.

v0.14.4 picks the cycle name **"Story Coverage"** because the
load-bearing slice is the test coverage that closes the
diagnostic-story + secure-snapshot coverage gap. The other
slices are doc-rot cleanup that landed alongside it.

## What this cycle ships

### Slice 1 — `story.rs` + `anonymize.rs` test coverage (Tier A, Rust only)

This is the headline slice. 52 unit tests across two modules:

- **32 tests in `story.rs`**:
  - `Severity::from_str` bucketing (critical / warning /
    unknown → info). The invariant: unparseable severity
    strings fall back to `Info`, never panic.
  - `Severity` ordering: `Critical > Warning > Info`.
  - `priority_for`: severity → priority number
    (1 / 2 / 3).
  - `parse_cost_range`: single value (`$150`), tilde
    (`~$150`), hyphen range (`$150-300`), **en-dash**
    (`$150–300` — the TOML files use en-dash; the parser
    must normalise), whitespace-padded, empty (→ None),
    garbage (→ None, no panic).
  - `format_vehicle`: empty (→ "Vehicle information
    unavailable"), VIN-only, mileage-only (16093 km → 10002
    mi via the `1.609` divisor + f64 rounding), decoded
    (manufacturer + model_year + WMI).
  - `build_context`: no freeze frame → default message;
    with freeze frame → "Freeze frame: RPM = 850; Coolant
    = 92°C; …".
  - Full `generate()` pipeline integration:
    - Empty snapshot → Info story, no findings,
      max-cost = 50 (the `cost_max.max(cost_min + 50)`
      invariant even with no findings).
    - Unknown DTC → generic Info finding, no engine note.
    - n55-specific DTC (`2A82` VANOS) → uses the n55
      template, severity = Warning.
    - Generic-only DTC (`P0171`) on n55 car → falls back to
      generic template.
    - Severity = max of all findings (sorted
      critical-first).
    - Recommendations sorted ascending by priority.
    - Cost range sums across findings (`$80–220 + $350–500`
      → min 430, max 720).
    - Cost-max invariant: `max >= min + 50` even when all
      ranges collapse to a single value.
    - DTC code case-insensitive lookup (TOML keys are
      uppercased on load; mixed-case snapshot codes still
      find them).
    - Summary text counts critical + warning correctly
      ("1 critical issue(s); 2 warning(s)").
    - Title uses manufacturer + VIN prefix.

- **20 tests in `anonymize.rs`**:
  - `hash_vin` properties: 16 hex chars, stable for same
    input, distinct for distinct inputs, case-sensitive
    pinned (an INVARIANT test — if we later normalise to
    upper-case per ISO 3779, this test will fail and force
    a privacy-claim review).
  - `anonymize()` pipeline:
    - VIN never leaks into the anonymized JSON
      (substring check against the known VIN).
    - VIN → vehicle_fingerprint via `hash_vin(vin)`.
    - Missing VIN → "unknown" fingerprint.
    - `engine_family` preserved from `suggested_profile`.
    - `engine_family` defaults to "generic" when no profile.
    - Modules / DTCs / freeze frames / ident all preserved.
    - **Mileage is stripped** (privacy — substring check
      against the original `mileage_km` value).
    - Empty modules handled.
    - `fault_count = None` → 0 in the anonymized output.
    - `recorded_at` populated with "(UTC)" suffix.
    - `live_data` is always empty (the current anonymizer
      strips it; pins the decision so future refactors don't
      reintroduce it accidentally).
  - `export_json`:
    - No VIN leak in pretty JSON.
    - No mileage leak.
    - Pretty-printed (multi-line + 2-space indent).
    - Round-trips through `serde_json::from_str::<AnonymizedSnapshot>`.

The tests load the **live community knowledge base** via
`story::load()` (which reads `community/stories/*.toml`), so
they exercise the actual production code path — including
the `n55.toml` engine-specific templates. If a TOML entry
moves, breaks, or gets renamed, the integration tests catch
it.

This slice shipped in [PR #201](https://github.com/ohgeeceee/beemuu/pull/201)

### Slice 4 — `ci.yml` Tauri Linux sysdeps fix (Tier A, CI workflows)

## Open question for the maintainer

1. **Should `hash_vin` be case-normalised to upper-case per
   ISO 3779?** The current implementation is byte-sensitive
   (DefaultHasher on the raw `&str`), so `"wbajb1c50…"` and
   `"WBAJB1C50…"` produce different fingerprints. The test
   `hash_vin_case_sensitive` pins this as the current
   behaviour; if the maintainer wants ISO 3779
   case-insensitivity (which is the right thing to do — VINs
   are case-insensitive per spec), the fix is one line:
   `vin.to_uppercase().hash(&mut hasher)`. That fix would
   turn `hash_vin_case_sensitive` from a positive
   `assert_ne!` test into a failing test, signalling the
   intentional change. **Default: leave as-is** (current
   behaviour is correct in the sense that callers always
   pass the VIN in upper-case via the `read_vin` protocol
   path; case-normalisation is a follow-up if real-world
   snapshots ever show mixed-case VINs leaking through).

2. **Should the "Story Coverage" cycle plan name stay?** The
   forward-roadmap doc (`docs/forward_roadmap_14.4_to_16.9.md`)
   had v0.14.4 as "N62 Bench Verification" — gated on the E70
   owner's report. v0.14.4 ended up being "Story Coverage"
   instead. The forward-roadmap doc should be updated to
   reflect the actual cycle (deferred to v0.14.5 docs pass).
