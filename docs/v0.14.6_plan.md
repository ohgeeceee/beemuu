## Premise

The v0.14.5 release cut (PR #225, merged 2026-08-02T07:37:08Z
on `origin/main` @ `5743348`) closed the "Open & Committed"
cycle end-to-end: tag `v0.14.5` on `origin` at `9249b934`,
draft release promoted to public at <https://github.com/
ohgeeceee/beemuu/releases/tag/v0.14.5>, both Windows
installer assets attached (`BeeEmUu_0.14.5_x64-setup.exe`
+ `BeeEmUu_0.14.5_x64_en-US.msi`).

But the v0.14.5 close-out left **four docs rot findings**
on `main` that need to ship as a follow-up cycle:

1. **`ROADMAP.md` v0.14.5 cycle block** is still marked
   "In Progress — slice 0" with all 3 slices `🔲 Open`.
   It should now be "Shipped 2026-08-02" with all 3
   `✅ Done` rows + the v0.14.5 release cut reference.
2. **`docs/forward_roadmap_14.4_to_16.9.md`** is the
   project's only forward-looking planning doc. The
   "Status (revised 2026-07-29)" blockquote lists 4 items
   as "already on main" — but 4 more cycles (v0.14.0
   through v0.14.4) have closed since the doc was
   written. The v0.14.4 candidate-slice list names the
   wrong cycle ("N62 Bench Verification" — actual: "Story
   Coverage" per the v0.14.4 release cut PR #208). The
   v0.14.5 candidate-slice list names the wrong cycle
   ("Bench Round 2" — actual: "Open & Committed" per
   the v0.14.5 release cut PR #225). The v0.15.0 entry's
   "DID-projection bridge" is the right next spine, but
   the v0.14.5 entry needs to be closed out first.
3. **`frontend/roadmap/v0.14.5.html`** (the public
   landing-page cycle detail shipped in PR #221) still
   claims v0.14.5 is "Planned" / "Tier TBD" / "Open &
   committed" with a candidate-slice list. It's now
   shipped. The next manual landing-page deploy (or the
   next `release.yml` run that succeeds the
   `Update beemuu.com landing page` step with the
   `BEEMUU_VPS_SSH_KEY` / `BEEMUU_VPS_HOST` secrets
   configured) will pick up the updated HTML.
4. **The forward-roadmap doc + the public landing-page
   cycle detail are now out of sync** for v0.14.5
   specifically. The forward-roadmap has v0.14.5 as
   the "next active" cycle; the public page has
   v0.14.5 as "Planned" / "Tier TBD". After this
   v0.14.6 cycle, they should be in lockstep: v0.14.5
   closed, v0.14.6 = Forward Roadmap Audit, v0.15.0
   the next feature cycle.

v0.14.6 picks the cycle name **"Forward Roadmap Audit"**
because the load-bearing slice is the docs-rotation
audit that the v0.14.4 cycle established as the
close-of-cycle pattern. The cycle is **single-slice,
Tier A, docs only** — the audit is small enough that a
3-PR shape (the v0.14.5 / v0.14.3 / v0.14.2 cycle
pattern) would be over-engineering.

## What this cycle does NOT ship

- ❌ No `transport/**` code changes. K+DCAN / ENET /
  DoIP paths are preserved. The forward-roadmap doc's
  Tier B candidate for the next-feature cycle
  (ENET/DoIP UDP broadcast discovery, the highest-
  leverage Tier B item) is preserved as a 🟡 item
  deferred to v0.15.0+ per the forward-roadmap's
  `v0.16.0` cycle spine (BLE / WiFi / ENET land rush).
- ❌ No `protocol/**` code changes.
- ❌ No `commands.rs` changes.
- ❌ No new crates in `src-tauri/Cargo.toml`.
- ❌ No frontend changes (no `src/js/**`, no
  `src/css/**`, no `src/index.html`). The
  `frontend/roadmap/v0.14.5.html` update is the
  only frontend file touched, and it's a
  landing-page-content change (not a JS / CSS
  app-shell change).
- ❌ No community data changes (`community/profiles/*.toml`,
  `community/stories/*.toml`, `community/testplans/*.toml`,
  `community/freeze/*.toml`).
- ❌ No new BMW hex descriptions.
- ❌ No `git tag v0.14.6`. That's the Tier C release
  cut, the next step after the v0.14.6 slice lands.
  Per the v0.14.5 release cut PR #225 model, the
  v0.14.6 release cut is a separate PR that bumps
  the version surface in `package.json` +
  `src-tauri/Cargo.toml` + `src-tauri/tauri.conf.json`
  + `src-tauri/Cargo.lock` + the README release badge
  + the CHANGELOG date stamps, with the maintainer
  running `git tag v0.14.6 && git push --tags` to
  trigger `release.yml` after the PR merges.
- ❌ No `BEEMUU_VPS_SSH_KEY` / `BEEMUU_VPS_HOST`
  secret configuration. The v0.14.5 release run
  (#30738207436) failed at the "Update beemuu.com
  landing page" step because these secrets aren't
  configured in the repo. The v0.14.6 release run
  will have the same failure mode until the
  maintainer configures the secrets. The v0.14.6
  cycle doesn't claim to fix this — it's a
  separate ops task that the maintainer owns.

## Open question for the maintainer

1. **Should the v0.14.6 release cut be a separate
   PR (mirror of v0.14.5 PR #225), or skipped
   entirely?** The v0.14.6 cycle's only slice is
   docs-only — the version surface in
   `package.json` / `Cargo.toml` / `tauri.conf.json`
   / `Cargo.lock` / `README.md` doesn't strictly
   need to move from `0.14.5` → `0.14.6` for the
   docs changes to be live. **Default:** the
   v0.14.6 release cut IS a separate PR
   (per CLAUDE.md golden rule #5 "don't let the
   badge lie" — the README release badge reflects
   the most recent **fully shipped** release, and
   a docs-only cycle still counts as shipped). If
   the maintainer wants to skip the v0.14.6
   release cut, the badge stays at `v0.14.5` and
   the v0.14.6 docs ship on the `v0.14.5` cycle.
2. **Should the v0.14.5 public landing page
   (`frontend/roadmap/v0.14.5.html`) link to the
   v0.14.5 release page
   (`https://github.com/ohgeeceee/beemuu/releases/
   tag/v0.14.5`)?** Yes — the install instructions
   are the load-bearing public surface for the
   cycle close-out. **Default:** add a "Download
   v0.14.5" button at the bottom of the
   `v0.14.5.html` page that links to the release
   page, matching the v0.11.0 walkthrough bundle
   pattern (PR #142).
